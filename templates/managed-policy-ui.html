Shuns, auto-restoration and protection — what is the difference? {% if overview %}

Auto-restore rules tell the service which addresses to keep blocked. Auto-restore off means no future restoration — not automatic unblocking. The last device check shows whether a block was observed, independently of this setting.

Turn off auto-restore only leaves the device unchanged. Turn off auto-restore and remove block also requests an unblock after confirmation. Neither interrupts a command already running.

{% endif %}
Shuns
Blocks seen on the devices during the last successful reads. Searching also includes clearly labelled historical records.
Managed shuns · Auto-restore on
The service keeps these addresses blocked and restores a missing block, subject to service pauses and device safety checks.
Managed shuns · Auto-restore off
No future restoration. This does not remove an existing block or automatically remove a later block created by FTD. Already running commands may still finish.
Protected IPs · Protection enabled
If the address is found blocked, the service requests removal. Protection permanently stops matching auto-restoration; disabling protection does not turn the old rule back on.
