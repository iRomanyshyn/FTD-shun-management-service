Host-assisted recovery

The current recovery procedure requires API, Web and agent to stop cleanly. The Web service intentionally has no Docker or host-control access. Run the command below on the Docker host, from this repository with its Python environment active. This is not a one-click browser recovery.

The helper stops the laboratory services, checks actual clean exits, rehearses recovery on a copy, creates a checked private backup and records a fresh decision for the exact held session. It retains original policy and unknown outcomes, then restarts the same services. The worker must obtain a fresh complete FTD read before continuing; only currently missing addresses may receive new attempts under current rules.

Do not close the terminal during recovery. A failure after stopping leaves the services stopped for inspection; it does not force-release a hold or erase evidence. Pending cleanup, foreign uncertainty, changed scope and unsupported failures refuse.
